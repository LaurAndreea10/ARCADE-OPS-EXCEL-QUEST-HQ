01 · PROBLEM

De ce încă un proiect de portofoliu?

Why another portfolio project?

Recruiterii care evaluează portofolii front-end văd zilnic aceleași 3-4 pattern-uri: landing pages, todo apps, weather dashboards, calculator apps. Toate frumoase, toate corecte. Nicio diferențiere reală.

Întrebarea pe care mi-am pus-o nu a fost "ce mai pot construi?" ci "ce demonstrează capacitatea mea de a construi un produs întreg, nu doar o piesă din el?"

Răspunsul: un univers. Nu un joc, nu un dashboard, nu un calculator. Un sistem care combină gameplay, progresie, learning design, identitate vizuală și engagement loops într-un singur produs coerent.

Front-end recruiters reviewing portfolios see the same 3-4 patterns every day: landing pages, todo apps, weather dashboards, calculators. All beautiful, all correct. No real differentiation.

The question I asked wasn't "what else can I build?" but "what demonstrates my capacity to build an entire product, not just a piece of one?"

The answer: a universe. Not a game, not a dashboard, not a calculator. A system combining gameplay, progression, learning design, visual identity, and engagement loops into one coherent product.

Problema reală nu era "ce să construiesc", ci "cum demonstrez că pot proiecta un sistem întreg, nu doar features". The real problem wasn't "what to build", but "how do I demonstrate I can design a whole system, not just features".
02 · CONCEPT

Patru piloni, un univers

Four pillars, one universe

Înainte de orice linie de cod, am stabilit cei 4 piloni care definesc fiecare decizie din proiect. Dacă o feature nu servește unul dintre ei, nu intră.

Before any line of code, I defined the 4 pillars guiding every decision. If a feature doesn't serve one of them, it doesn't ship.

① Rapid & satisfăcătorFast & satisfying

Input rapid, feedback instant. Combo bursts vizuale. Sound design sintetizat în Web Audio API care reacționează la combo-ul curent. Delay-ul maxim între input și răspuns vizual: 16ms.

Fast input, instant feedback. Visual combo bursts. Sound synthesized in Web Audio API that reacts to current combo. Maximum delay between input and visual response: 16ms.

② Inteligent & utilSmart & useful

Gameplay-ul nu e arbitrar. Triage Rush folosește categorii reale de prioritizare (P1 outage, GDPR, vendor disputes). Formula Lab cere puzzle-uri Excel pe care le folosești efectiv în muncă (VLOOKUP, INDEX-MATCH, IFERROR). Joci și înveți simultan.

Gameplay isn't arbitrary. Triage Rush uses real prioritization categories (P1 outage, GDPR, vendor disputes). Formula Lab asks Excel puzzles you actually use in work (VLOOKUP, INDEX-MATCH, IFERROR). You play and learn simultaneously.

③ Stilizat & memorabilStylized & memorable

Identitatea vizuală e neon-arcade, mix între SaaS dashboard și control room cyber. 3 fonturi (Orbitron pentru display, Rajdhani pentru body, JetBrains Mono pentru cod), paletă magenta-cyan-purple cu accente lime și orange. Atmosphere layers (grid + aurora) pentru depth fără overhead.

Visual identity is neon-arcade, mix between SaaS dashboard and cyber control room. 3 fonts (Orbitron for display, Rajdhani for body, JetBrains Mono for code), magenta-cyan-purple palette with lime and orange accents. Atmosphere layers (grid + aurora) for depth without overhead.

④ Driven de progresieProgression-driven

8 ranguri (Trainee → Master Operator), 33 achievements pe 4 tier-uri (common, rare, epic, legendary), 6 districte unlock-abile progresiv, daily challenges cu streak system, customization cu coins. Trei tipuri de progresie suprapuse: core loop (per-mission XP), meta loop (rank-up), long-term loop (achievement collection + streak).

8 ranks (Trainee → Master Operator), 33 achievements across 4 tiers (common, rare, epic, legendary), 6 progressively-unlocked districts, daily challenges with streak system, customization with coins. Three overlapping progression types: core loop (per-mission XP), meta loop (rank-up), long-term loop (achievement collection + streak).

03 · KEY DECISIONS

Decizii care au modelat proiectul

Decisions that shaped the project

Decizia tehnică
Technical decision
Single-file, fără build tools
Single-file, no build tools

Toată aplicația — HTML, CSS, JS, sound engine, i18n, state management — într-un singur index.html de 240KB. Zero npm install, zero webpack, zero node_modules. Open în browser, joacă imediat.

The whole app — HTML, CSS, JS, sound engine, i18n, state management — in a single 240KB index.html. Zero npm install, zero webpack, zero node_modules. Open in browser, play immediately.

De ce: recruiterul nu va clona repo-ul și nu va rula npm install. Vrea să apese link-ul și să joace. Reducerea fricțiunii la zero a fost mai importantă decât arhitectura "corectă".

Why: the recruiter won't clone the repo and run npm install. They want to click the link and play. Reducing friction to zero was more important than "correct" architecture.

Trade-off acceptat
Accepted trade-off
240KB într-un singur fișier vs modular cu code splitting
240KB in one file vs modular with code splitting

Un fișier de 240KB încarcă tot, indiferent dacă userul ajunge sau nu la boss fight. Code splitting ar fi tehnologic "mai corect", dar adaugă complexitate (build step, lazy loading) pentru un beneficiu real de ~30KB. Trade-off acceptat: simplicitate > optimizare prematură.

A 240KB file loads everything, whether the user reaches the boss fight or not. Code splitting would be "more correct" technically, but adds complexity (build step, lazy loading) for ~30KB real benefit. Accepted trade-off: simplicity > premature optimization.

Decizia de UX
UX decision

5-step onboarding, not zero-effort start

Inițial planificasem să las jucătorul direct în Hub fără niciun ghidaj. Greșeală. Recruiterii care testează 30 de secunde nu înțeleg ce e Triage Rush și pleacă confuzi. Am adăugat un overlay 5-step: welcome → Triage → Formula → Progression → Districts. Skip option oricând.

I initially planned to drop the player directly into the Hub with no guidance. Mistake. Recruiters testing for 30 seconds don't understand what Triage Rush is and leave confused. I added a 5-step overlay: welcome → Triage → Formula → Progression → Districts. Skip option anytime.

Lecția: "designerul vede întreaga structură în mintea lui". Userul nou vede 8 butoane fără context. Onboarding-ul costă 30 secunde. Confuzia costă userul.

Lesson: "the designer sees the whole structure in their mind". The new user sees 8 buttons without context. Onboarding costs 30 seconds. Confusion costs the user.

Decizia audio
Audio decision
SFX sintetizate vs samples
Synthesized SFX vs samples

Aș fi putut descărca sample-uri de SFX arcade. Dar asta ar fi adăugat 50-100KB extra și fricțiune (cors, encoding, fallbacks). Am construit un mini sound engine cu Web Audio API: oscillator + envelope + filter. Toate sunetele jocului — click, success arpeggio, combo escalation, boss hit, rank-up flourish — sunt generate live, în ~150 linii de cod.

I could have downloaded arcade SFX samples. But that would have added 50-100KB extra and friction (cors, encoding, fallbacks). I built a mini sound engine with Web Audio API: oscillator + envelope + filter. All game sounds — click, success arpeggio, combo escalation, boss hit, rank-up flourish — are generated live, in ~150 lines of code.

All 25 triage tasks and 21 Excel puzzles are written in both languages. UI toggles live with a HUD button. Cost: double copywriting effort (~250 strings). Benefit: I show I can architect an i18n system without external libraries, and I'm visible to recruiters in both markets.

04 · CHALLENGES

Provocările reale

The real challenges

a. Game feel cu zero biblioteciGame feel with zero libraries

"Game feel" e termenul pentru senzația tactilă a jocului — combinația dintre input lag, visual feedback, audio response și juiciness. Engine-uri ca Phaser sau Pixi îl rezolvă out-of-the-box. Eu nu am avut acela. A trebuit să construiesc:

"Game feel" is the term for the tactile feeling of a game — the combination of input lag, visual feedback, audio response, and juiciness. Engines like Phaser or Pixi solve it out-of-the-box. I didn't have that. I had to build:

  • Combo bursts: elemente DOM care se animează cu CSS keyframes la fiecare succes consecutiv.
  • Combo bursts: DOM elements animated with CSS keyframes on each consecutive success.
  • Screen feedback: flash subtil de culoare pe success/fail, fără a deranja focusul.
  • Screen feedback: subtle color flash on success/fail, without disrupting focus.
  • Pitch escalation: sunetul crește în frecvență cu combo-ul (60Hz × combo level).
  • Pitch escalation: sound rises in frequency with combo (60Hz × combo level).
  • Toast badges: notificări care apar în lateral cu micro-animații staggered.
  • Toast badges: side-appearing notifications with staggered micro-animations.

b. Echilibrarea progresieiBalancing progression

Cea mai mare lecție a proiectului. Prima versiune dădea prea mult XP — userul ajungea Master Operator în 10 minute. Refac-uri succesive:

The biggest lesson of the project. The first version gave too much XP — the user reached Master Operator in 10 minutes. Successive reworks:

Înainte

Before

XP plat, fără bonus pentru combo sau accuracy. Coins prea generoase. Nimic nu se simțea câștigat.

Flat XP, no bonus for combo or accuracy. Coins too generous. Nothing felt earned.

După

After

XP de bază + bonus combo (×25/level) + speed bonus + perfect run bonus + streak multiplier. Coins limitate la 30% din XP. Achievements împărțite pe 4 tier-uri ca să existe permanent o țintă vizibilă.

Base XP + combo bonus (×25/level) + speed bonus + perfect run bonus + streak multiplier. Coins capped at 30% of XP. Achievements split into 4 tiers so there's always a visible next target.

c. State management fără ReduxState management without Redux

Un obiect global state cu sub-obiecte pentru player, stats, mastery, achievements, customization, daily, streak. Persistat în localStorage la fiecare modificare prin saveState(). Migrarea între versiuni se face prin DEFAULT_STATE spread operator — câmpurile noi primesc default-uri, cele existente sunt păstrate. Zero data loss între v1 și v2.5.

A global state object with sub-objects for player, stats, mastery, achievements, customization, daily, streak. Persisted to localStorage on every modification via saveState(). Migration between versions uses the DEFAULT_STATE spread operator — new fields get defaults, existing ones are preserved. Zero data loss between v1 and v2.5.

06 · LESSONS LEARNED

Ce am învățat

What I learned

01

Scope creep e inamicul №1

Scope creep is enemy №1

V1 avea 4 game modes. La final v2.5 are 5 + daily + customize + onboarding. Fiecare adăugare a fost justificată, dar costul real e timpul de testing și rebalanceing. Lecția: taie 30% din scope și șlefuiește celelalte 70%, decât să faci 100% mediu.

V1 had 4 game modes. By v2.5 it has 5 + daily + customize + onboarding. Every addition was justified, but the real cost was testing and rebalancing time. Lesson: cut 30% of scope and polish the other 70% — better than 100% mediocre.

02

Audio schimbă tot

Audio changes everything

Adăugarea SFX-ului a fost ultima feature din v2. A făcut jocul să se simtă dublu de bun. Am subestimat masiv impactul. Lecția: sound design nu e "polish nice-to-have", e parte integrală din game feel.

Adding SFX was the last feature in v2. It made the game feel twice as good. I massively underestimated the impact. Lesson: sound design isn't "nice-to-have polish", it's integral to game feel.

03

Tier-urile de achievement contează

Achievement tiers matter

În v1 aveam 12 achievements, toate vizual identice. În v2.5 sunt 33 împărțite pe common/rare/epic/legendary cu styling diferit per tier. Aceeași informație, dar percepția de "merge să joc mai mult" se triplează.

V1 had 12 achievements, all visually identical. V2.5 has 33 split into common/rare/epic/legendary with per-tier styling. Same information, but the "worth playing more" perception triples.

04

Onboarding = retenție

Onboarding = retention

Înainte de onboarding, recruiterii care testau 30 sec apoi părăseau pagina. După: înțelegeau jocul în 60 sec și jucau 5+ minute. Cele mai bune 30 secunde de UX investit din proiect.

Before onboarding, recruiters tested for 30s and left. After: they understood the game in 60s and played 5+ minutes. The best 30 seconds of UX investment in the entire project.

05

Bilingv = dublu efort, dublu reach

Bilingual = double effort, double reach

RO/EN dublu efort de scris content, dar mă pune pe radar atât pentru piața locală cât și pentru cea internațională. Dovedește că pot proiecta i18n end-to-end, ceea ce e o skill rar testată în portofolii.

RO/EN doubles the content effort, but puts me on the radar for both local and international markets. It proves I can architect i18n end-to-end, a rarely-tested skill in portfolios.
